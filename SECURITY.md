# Security policy

## Supported versions

| Version | Supported |
|---------|-----------|
| 1.x     | ✅        |

## Reporting a vulnerability

Please do **not** open a public issue for a security problem.

Use GitHub's private vulnerability reporting form:
<https://github.com/vikasdocker/android-device-portal/security/advisories/new>

You can also email the BlueFluteX team at <vikasshu7@gmail.com> with the subject
`[security] Android Device Portal`. Please do not include exploit details in a
public issue.

Include:

- A description of the issue and its impact.
- Steps to reproduce, or a minimal proof of concept.
- Affected version or commit.
- Any suggested mitigation.

You can expect an acknowledgement within 72 hours. Please give the maintainer
reasonable time to release a fix before public disclosure.

## Security model

This project is designed to run on a trusted local machine or trusted LAN:

- The portal listens on `127.0.0.1:8080` in no-Docker mode. The Docker
  configuration publishes it on `8080`; bind it to localhost if the machine is
  not fully trusted.
- The host agent listens on port `8765` and requires the `X-Agent-Token` header
  for every request. The token is generated by `install-agent.ps1` and stored
  in `.env` and `host-agent/agent-config.json`; neither file is committed.
- Screenshots are proxied by the portal so the agent token never reaches the
  browser.
- Run artifacts (screenshots, logcat, `meminfo.txt`) can contain sensitive app
  data. Treat `data/` as private and do not attach raw artifacts to public
  issues.

## Hardening checklist

- Use a long, random `AGENT_TOKEN` (the installer generates one).
- Keep TCP `8765` blocked at the firewall except for the portal host.
- Do not expose the portal or agent directly to the internet; put them behind a
  VPN or an authenticated reverse proxy if remote access is required.
- Rotate the token if it was ever committed, logged, or shared.
- Review uploaded APK/AAB files before running them on an emulator.

## Dependency and secret hygiene

- CI runs lint and tests on every push and pull request.
- Dependabot proposes dependency updates weekly.
- `.env`, `host-agent/agent-config.json`, `data/`, and `tools/` are ignored.
  If you believe a secret was committed, rotate it immediately and purge it
  from git history.
